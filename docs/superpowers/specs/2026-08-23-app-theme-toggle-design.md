# OpenGZH 应用浅色主题切换设计

**日期：** 2026-08-23

**状态：** 用户已确认首次默认浅色、切换后记忆，并选择 A「纸墨暖白」

## 目标

在现有深色「墨岩珊瑚」基础上增加同系列浅色主题「纸墨暖白」，允许用户从顶栏切换应用界面深浅色并持久记忆。应用主题与文章预览深色模式继续保持独立，不改变文章、封面、小红书卡片或导出产物。

成功标准：

- 首次访问、存储缺失或存储值非法时默认使用浅色。
- 用户切换后刷新页面仍保持上次选择，且已保存的深色在首屏样式绘制前生效，不出现明显浅色闪烁。
- 封面图、文本和图片三种工作区都消费同一套深浅语义 token。
- 应用主题切换与文章预览深色模式在位置、文案和状态上可以明确区分。
- 两套主题的正文、弱文字、强调操作、错误与警告状态均满足正常文字至少 `4.5:1` 的对比度要求。

## 已确认的产品决策

- 默认主题：A「纸墨暖白」。
- 备选主题：保留当前深色「墨岩珊瑚」。
- 记忆方式：用户每次切换后写入浏览器本地存储。
- 不跟随 `prefers-color-scheme`，不提供“跟随系统”第三状态。
- 不增加设置面板；切换入口固定放在顶栏右侧。
- 继续直接在 `main` 实施，未单独授权前不推送远程。

### 深色「墨岩珊瑚」

完整保留当前语义色板：

- 背景 `#181512`、次级背景 `#211D19`、抬升面板 `#29231E`。
- 主文字 `#FFF7ED`、珊瑚强调 `#FF8A76`、强调上文字 `#26120F`。
- 错误文字 `#FF9A9A`、警告文字 `#FBBF70`。

浅色与深色分别定义阴影、原生控件 `color-scheme` 和语义状态色，不让为深色优化的浅红/浅黄文字泄漏到浅色界面。

## 交互设计

### 应用主题切换

- 在空置的 `.header-right` 中放置一个图标按钮。
- 当前为浅色时显示月亮，按钮动作与 `aria-label` 为“切换到深色界面”。
- 当前为深色时显示太阳，按钮动作与 `aria-label` 为“切换到浅色界面”。
- 按钮使用现有 header 控件尺寸、边框、悬停与焦点规则，不新增文字占位，保证窄屏头部不进一步拥挤。

### 与文章预览模式区分

- 顶栏按钮只改变应用外壳。
- 预览工具栏现有按钮只改变 `renderedContent` 的观察方式。
- 现有预览按钮的 `title` 与 `aria-label` 改为“文章预览切换到深色/浅色”，不再使用容易被理解为全局主题的“切换到深色模式”。
- 两个状态互不联动、互不持久化替代。

## 技术方案

采用“CSS 双语义色板 + 小型主题状态模块 + 首屏同步引导脚本”。

### CSS 主题边界

- `:root` 定义默认浅色色板。
- `:root[data-app-theme="dark"]` 覆盖深色色板、阴影、语义状态色与 `color-scheme`。
- 现有 `editor.css`、`panel.css`、`cover.css`、`xhs.css` 继续消费共享变量。
- 将应用壳中只适合深色背景的错误/警告字面量收敛为 `--color-danger`、`--color-warning`；不修改 `.xhs-card` 输出主题内部色值。

### 主题状态模块

新增 `assets/scripts/ui/app-theme.js`，职责仅包含：

- `normalizeAppTheme(value)`：仅接受 `light` / `dark`，其余回落到 `light`。
- `readStoredAppTheme(storage)`：读取 `opengzh-app-theme`，存储异常时返回 `light`。
- `applyAppTheme(theme, root, storage, persist)`：更新 `documentElement.dataset.appTheme`，可选持久化；即使存储写入失败也保留当前页面的视觉切换。
- `toggleAppTheme(theme)`：在 `light` / `dark` 之间切换。

`main.js` 只维护一个响应式 `appTheme`，调用该模块并向模板暴露当前状态与切换动作，不把应用主题塞进文章/文档的 `savePreferences()` 数据模型。

### 首屏防闪烁

在 `index.html` 的 CSS 引用之前放置极小的同步脚本：读取同一存储键，只有精确值 `dark` 才设置深色，否则设置浅色。

这是有意保留的一处键名与二值校验重复：同步脚本必须在 ES Module 和 Vue 启动前运行，才能避免已保存深色的首屏闪烁。使用 `ponytail:` 注释标明：若未来主题状态超过两个，再升级为共享的阻塞式 bootstrap 文件。

## 数据流与异常处理

1. 页面解析 `<head>`，同步脚本把合法存储值写入 `html[data-app-theme]`。
2. CSS 根据属性选择浅色或深色 token。
3. Vue 初始化时从根节点属性建立 `appTheme`，避免第二次存储读取产生不一致。
4. 用户点击顶栏按钮，模块立即更新根节点属性和响应式状态，再尝试写入存储。
5. `localStorage` 不可读时默认浅色；不可写时当前页面仍能切换，但刷新后回到浅色。

不弹出阻塞式错误提示：主题持久化失败不影响内容编辑，也不应干扰写作流程。

## 输出真相边界

以下区域不继承应用主题决定其内容配色：

- `renderedContent` 内的文章主题、代码主题、卡片样式和表格图片。
- 封面 SVG/PNG 的画布、文字与装饰。
- `.xhs-card` 及导出的单页 PNG、ZIP。
- 复制到公众号的 HTML 与导出协议。

应用外壳可以改变这些内容周围的工作台颜色，但不得改写其渲染数据或内联样式。

## 验证设计

### 自动化

- 主题状态模块：默认值、非法值、读取异常、写入异常、切换和持久化。
- CSS 合同：浅色与深色核心 token、两套对比度、语义错误/警告色和填充按钮文字。
- HTML 合同：首屏引导脚本位于 CSS 之前；顶栏按钮具有动态 `title` / `aria-label`；文章预览按钮文案明确。
- 运行全量 `npm test`、相关 `node --check` 与 `git diff --check`。

### 真实浏览器

- 清空主题存储后刷新，确认首次为浅色。
- 切换到深色并刷新，确认保持深色且无明显浅色闪烁；再切回浅色并刷新。
- 在封面图、文本、图片三种模式分别检查两套应用主题。
- 检查主题/排版弹层、表单、警告错误状态、键盘焦点与原生选择控件。
- 在 `1440×900` 和 `390×844` 检查按钮可达性与已有布局。
- 确认文章白纸、封面 SVG 与小红书卡片在切换前后配色不变，浏览器控制台无错误。

## 非目标与回滚

- 不跟随系统主题，不支持第三套主题，不提供定时切换。
- 不改布局、字体、Logo、文章主题、封面模板、小红书主题或导出协议。
- 不重构现有通用偏好存储或将应用主题绑定到每篇文档。
- 功能无数据迁移；回滚相关 CSS、主题模块、模板和缓存版本即可。旧的 `opengzh-app-theme` 键即使残留也不会影响回滚后的版本。
