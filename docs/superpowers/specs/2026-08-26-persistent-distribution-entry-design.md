# OpenGZH 常驻分发入口设计

## 目标

OpenGZH 网页在未安装 Chrome 扩展时也始终显示“同步到平台”按钮。用户点击后：

- 扩展可用：直接打开现有多平台分发面板。
- 扩展不可用且 Chrome Web Store 地址为空：显示 Toast“OpenGZH 插件即将上线 Chrome 商店”。
- 扩展不可用且以后配置了商店地址：在新标签页打开该地址。

本次只调整入口归属和点击协作，不改变微信公众号、知乎、掘金、人人都是产品经理的登录检测、图片上传、草稿保存和打开草稿流程。

## 现状与根因

网页目前只在“复制到公众号”按钮上提供 `data-opengzh-copy-button` 锚点；“同步到平台”按钮由 MV3 内容脚本注入。未安装、未启用或尚未加载扩展时，内容脚本不会执行，因此页面没有任何分发入口。

## 方案

采用“网页拥有入口，扩展拥有能力和面板”的单入口方案。

### 网页入口

网页在现有“复制到公众号”旁直接渲染“同步到平台”按钮，并继续保留稳定锚点供扩展挂载 Shadow DOM 面板。按钮不因扩展是否安装而隐藏，也不因文章正文为空而禁用。

点击按钮时，网页：

1. 生成一次性 `requestId`。
2. 先监听扩展确认事件。
3. 派发 `opengzh:distribution:open`，只携带 `requestId`。
4. 在 500ms 内收到相同 `requestId` 的确认后结束，不显示安装提示。
5. 超时未收到确认时，按 Chrome Web Store 地址执行降级行为。

商店地址使用网页侧常量，初始值为空字符串。为空时调用现有 Toast，文案固定为“OpenGZH 插件即将上线 Chrome 商店”；非空时通过 `window.open(url, '_blank', 'noopener')` 打开，不在当前页跳转。

### 扩展接管

内容脚本继续只注入允许的 OpenGZH 域名。它不再创建自己的“同步到平台”触发按钮，只创建现有 Shadow DOM 面板。

内容脚本监听 `opengzh:distribution:open`。收到非空字符串 `requestId` 后：

1. 确认内容脚本仍连接到扩展服务。
2. 打开现有分发面板。
3. 派发 `opengzh:distribution:opened`，原样返回 `requestId`。

无效、空白或非字符串 `requestId` 一律忽略。确认事件不携带扩展 ID、版本、登录态、文章数据或其他敏感信息。

### 挂载与生命周期

网页按钮是唯一可见入口。扩展 Shadow DOM host 仍挂载在该按钮附近，但 host 本身不占用额外按钮位置。

网页每次点击都进行一次带超时的请求—确认，而不是缓存“已安装”状态。这样扩展在页面打开期间被禁用、重载或断开时，不会留下过期安装状态；下一次点击会自然进入未安装降级流程。

网页在收到确认或超时后移除本次监听器并清理计时器。扩展销毁 UI 时移除打开事件监听器，继续复用现有 port 断开与 UI dispose 逻辑。

## 交互与可访问性

- 按钮文案固定为“同步到平台”，沿用工具栏按钮的视觉语言。
- 按钮使用原生 `<button type="button">`，可键盘聚焦和触发。
- 扩展打开后继续使用现有 `role="dialog"`、焦点与关闭逻辑。
- 未安装提示使用现有 Toast，不新增弹窗。
- 连续点击各自使用独立 `requestId`；扩展面板已打开时只保持打开状态，不创建第二个面板。

## 事件契约

| 事件 | 方向 | detail | 作用 |
| --- | --- | --- | --- |
| `opengzh:distribution:open` | 网页 → 扩展 | `{ requestId: string }` | 请求打开分发面板 |
| `opengzh:distribution:opened` | 扩展 → 网页 | `{ requestId: string }` | 确认扩展已接管本次点击 |
| `opengzh:distribution:request` | 扩展 → 网页 | 既有契约 | 请求生成文章快照 |
| `opengzh:distribution:ready` | 网页 → 扩展 | 既有契约 | 返回文章快照 |
| `opengzh:distribution:error` | 网页 → 扩展 | 既有契约 | 返回安全错误 |

本次不修改后三个既有文章快照事件。

## 失败处理

- 未安装、未启用、匹配域名不正确、内容脚本尚未就绪或扩展已断开：500ms 后执行商店降级。
- 商店地址为空：只显示固定 Toast，不打开空白页。
- 商店地址非法：视同为空，不调用 `window.open`。
- 扩展确认晚于超时：网页已清理监听器，不再改变本次结果；面板若随后打开也保持幂等。
- 扩展已加载但无法连接 service worker：不发送确认，让网页进入降级流程；不向页面暴露内部错误。

## 最小改动范围

- `index.html`：增加常驻按钮，原“复制到公众号”功能不变。
- `assets/scripts/distribution/extension-bridge.js`：增加网页侧打开请求、确认等待和商店降级逻辑。
- `assets/scripts/main.js`：把现有 Toast 和窗口能力接入网页侧入口。
- `extension/src/content/open-gzh.js`：移除注入触发按钮，监听打开请求并打开现有面板。
- 对应网页桥接测试、内容脚本测试和静态入口测试。

不新增依赖，不改平台适配器，不改 Manifest 权限和 host 范围。

## 验收标准

1. 未安装或禁用扩展时，OpenGZH 页面仍显示且只显示一个“同步到平台”按钮。
2. 商店地址为空时点击按钮，只出现“OpenGZH 插件即将上线 Chrome 商店” Toast，不打开新窗口。
3. 配置合法商店地址后，扩展不可用时点击按钮在新标签页打开商店。
4. 扩展已安装并连接时，点击同一按钮直接打开现有四平台分发面板，不显示安装提示。
5. 页面和扩展之间只接受同一 `requestId` 的确认；超时、迟到和无效确认不会污染其他点击。
6. 重复点击不会创建重复按钮、重复 host 或重复面板。
7. 原“复制到公众号”、文章快照生成和四平台草稿链路保持通过。
8. 扩展禁用后刷新页面，常驻按钮仍存在并进入未安装提示；重新启用和刷新后可直接打开面板。

## 验证方式

- 网页桥接单测：确认、超时、空地址 Toast、有效地址跳转、错误 `requestId`、监听器清理。
- 内容脚本单测：唯一入口、不再创建触发按钮、有效打开请求、无效请求、断开状态、幂等打开。
- 静态检查：`index.html` 永久包含“同步到平台”和稳定锚点。
- 全量测试、扩展专项测试、扩展构建、语法检查和 `git diff --check`。
- 真实 Chrome：分别在未加载扩展、加载扩展、禁用扩展并刷新三种状态下验证上述行为。
