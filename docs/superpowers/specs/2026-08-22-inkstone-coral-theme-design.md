# OpenGZH 「墨岩珊瑚」全局界面主题设计

**日期：** 2026-08-22

**状态：** 用户已确认 B 方案、深色暖墨岩方向及直接修改 `main`

## 目标

将当前「深海夜航」冷蓝工作台替换为更温暖、具有内容编辑气质的「墨岩珊瑚」主题，覆盖封面图、文本和图片三种工作区。主题只改变应用外壳与操作控件，不改变文章、封面和小红书图片的真实输出样式。

成功标准：

- 顶栏、编辑区、侧栏、工具栏、下拉面板、弹窗和状态反馈形成统一的暖深色界面。
- 主次文字、弱提示、填充按钮和键盘焦点均满足清晰可辨的对比度要求。
- 微信文章预览、封面 SVG/PNG、小红书卡片和复制/导出产物在换肤前后保持原有内容配色与尺寸。

## 产品决策

- 「墨岩珊瑚」直接成为唯一默认应用主题，不新增主题切换器或用户偏好字段。
- 保持现有布局、字体、字号、间距、圆角和交互流程，只替换颜色、阴影及必要的状态色。
- 保留文章「深色预览」功能；它属于内容预览模式，不受应用外壳主题替换影响。
- 直接在 `main` 上实施和提交，不创建功能分支。

对比度约束：

- 主文字 / 抬升面板约 `14.61:1`。
- 弱文字 / 抬升面板约 `6.50:1`。
- 珊瑚强调 / 应用背景约 `7.92:1`。
- 强调上文字 / 珊瑚强调约 `7.78:1`。

上述组合均达到 WCAG AA 正常文字 `4.5:1` 的下限。错误、警告和成功色继续表达各自语义，不以珊瑚强调色替代。

## 应用范围

需要换色：

- 全局顶栏、模式切换、状态栏、滚动条、Toast、弹窗和遮罩。
- Markdown 编辑器、工具栏、拖拽分隔线、文章预览外围、主题与排版弹层。
- 封面模板列表、封面工具栏、内容表单、插图分类和导出操作。
- 图片模式工作区、设置栏、分页导航、封面编辑面板和下载操作。
- 通用按钮、输入框、选择器、滑杆、复选框、悬停、选中、禁用和键盘焦点状态。

必须保持原样的输出真相区：

- `renderedContent` 内的微信文章主题、代码块主题和卡片样式。
- 封面预览中的 SVG 画布、文字与装饰元素。
- `.xhs-card` 及其图片主题、封面图片和导出 PNG。
- 复制到微信的 HTML、表格 PNG、封面 PNG 与小红书 ZIP/PNG。

## 实现方案

采用“语义色板替换 + 定向清理残留冷蓝硬编码”：

1. 在 `assets/styles/base.css` 替换全局语义 token、强调透明底和阴影色。
2. 搜索五个应用样式文件中属于应用壳的旧蓝色字面量，仅替换确认会绕过 token 的部分。
3. 不新增 JavaScript、依赖或运行时主题层；现有组件继续消费同一组 CSS 变量。
4. 在 `assets/scripts/core/__tests__/app-theme.test.js` 更新主题合同，先观察旧色板导致测试失败，再实施最小样式修改。
5. 只为发生变化的 CSS 文件更新 `index.html` 查询版本，避免部署缓存继续显示旧主题。

预计涉及：

- `assets/styles/base.css`
- `assets/styles/editor.css`、`panel.css`、`cover.css`、`xhs.css`（仅在发现残留冷蓝字面量时）
- `assets/scripts/core/__tests__/app-theme.test.js`
- `index.html`

## 验证

- 主题合同测试锁定墨岩珊瑚 token、正常文字对比度和填充按钮文字规则。
- 运行全量 `npm test`、`git diff --check`，确保文章主题、封面和图片导出既有测试无回归。
- 在桌面宽度逐一检查封面图、文本、图片模式以及主题/排版弹层。
- 在 `390px` 下抽查应用主题可读性，不把既有响应式布局问题纳入本次换肤范围。
- 用键盘 Tab 检查主要操作焦点环，并确认浏览器控制台无错误。

## 非目标与回滚

- 不改 Logo、布局、字体、响应式结构、文章主题、封面模板或小红书主题。
- 不顺手整理与换色无关的 CSS，也不添加主题切换能力。
- 这是无数据迁移的 CSS 外观变更；如需回滚，回退对应实现提交即可。
