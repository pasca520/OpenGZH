# OpenGZH 卡片样式库设计

日期：2026-08-19

状态：设计已确认，待实施计划

范围：文本模式下的 10 张内置卡片；不包含全文样式定制或通用素材平台

## 1. 背景与目标

用户需要的不是全文主题覆盖，而是一组局部卡片：在左侧 Markdown 编辑器选中文字后套用卡片，或在没有选区时直接插入一张可编辑卡片。

本设计的目标是用最小结构打通完整闭环：

1. 编辑器选区能够安全套用卡片，原文零丢失。
2. 无选区时能够插入带占位内容的卡片。
3. 卡片随 Markdown 保存，可导入、导出、替换和无损移除。
4. 10 张卡片自动跟随当前文章主题色。
5. 预览、复制到微信公众号后的结构和样式保持一致。

## 2. 非目标

- 不提供全文颜色、字号、间距或元素级自由定制。
- 不提供自定义 CSS、样式刷子或用户自建模板。
- 不提供图片、SVG、视频、表单、二维码、时间轴或多栏布局组件。
- 不提供搜索、收藏、分类管理或远程素材市场。
- 不支持在右侧预览区选中文字后反向映射到 Markdown。
- 不新增后端、构建步骤或运行时依赖。

## 3. 已确认的产品决策

| 决策 | 结论 |
| --- | --- |
| 功能类型 | 局部卡片样式库，不是全文样式覆盖 |
| 选区来源 | 只读取左侧 Markdown 编辑器选区 |
| 选区边界 | 卡片是块级结构，应用到选区覆盖的完整段落 |
| 无选区行为 | 在光标处插入带占位内容的卡片 |
| 数据归属 | 卡片标记直接写入 Markdown；不保存字符范围元数据 |
| 原文保护 | 任何操作不得静默删除选中文字 |
| 入口 | 左侧编辑器工具栏新增“卡片”按钮 |
| 数量 | 10 张固定内置卡片 |
| 槽位 | 7 张单槽位、3 张标题与正文双槽位 |
| 配色 | 结构固定，颜色跟随当前文章主题语义色 |
| 重复应用 | 替换外层卡片 ID，不允许卡片嵌套 |
| 移除 | 只移除卡片标记，标题和正文原样保留 |
| 内容边界 | 支持普通段落、行内 Markdown 和普通列表；拒绝高风险块 |
| 面板布局 | 两列真实缩略图；移动端单列 |
| 自定义能力 | 首版无参数面板、搜索、收藏、分类和用户自建样式 |

范围收窄后，所有 10 张卡都是块级卡片。不要为本需求实现通用的 `inline | block | insert` 样式框架；“直接插入”是卡片操作方式，不是第三种样式类型。

## 4. 技术方案比较

### 方案 A：Markdown 指令 + 内置卡片注册表（采用）

Markdown 只保存稳定的卡片 ID 和内容，渲染时由注册表生成主题联动的内联样式。

优点：源码可读、能导入导出、能替换和无损移除、换主题后自动更新。缺点：需要一个轻量 markdown-it 块指令解析器。

### 方案 B：把完整 HTML/CSS 插入 Markdown

优点：初次实现快。缺点：源码噪声大，主题切换困难，替换和移除需要解析任意 HTML，长期维护成本最高。

### 方案 C：按字符位置保存样式元数据

优点：Markdown 表面干净。缺点：编辑文字后范围会漂移，跨设备导入导出会丢失状态，不符合 Markdown 为权威源的产品原则。

## 5. Markdown 数据契约

### 5.1 单槽位卡

```md
:::ogzh-card accent-bar
这里是卡片正文。
:::
```

### 5.2 标题与正文双槽位卡

标题使用标准四级 Markdown 标题，不再发明独立标题字段：

```md
:::ogzh-card capsule-title
#### 核心观点

这里是卡片正文。
:::
```

这样移除卡片后，标题和正文仍是有效 Markdown。

### 5.3 解析规则

- `styleId` 必须命中 10 张内置卡片白名单；禁止用户传入 class、style 或任意 CSS。
- 指令必须独占一行并成对闭合。
- 允许指令内部继续解析普通 Markdown 段落、行内格式和列表。
- 禁止卡片嵌套。应用新卡片时修改现有外层 `styleId`。
- 未知 `styleId` 应忽略卡片外观并正常显示内部内容，不能吞掉正文。
- 未闭合或结构损坏的指令按普通文本保留，不能猜测修复后重写用户内容。

## 6. 交互设计

### 6.1 工具栏入口

在左侧编辑器现有 Markdown 工具栏增加“卡片”按钮：

- 使用原生 `button`，提供 `aria-haspopup`、`aria-expanded` 和可见焦点。
- 面板桌面端两列、窄屏单列，展示真实结构缩略图和名称。
- 不提供分类、搜索、收藏和自定义入口。
- 面板底部放置“移除卡片”；仅当光标或选区位于卡片内时可用。
- `Esc` 关闭面板，点击外部关闭；关闭动作不得覆盖已缓存的编辑器选区。

### 6.2 有选区时套用

1. 读取当前缓存的 `selectionStart` 和 `selectionEnd`。
2. 先识别选区或光标是否位于同一张现有卡片内；若是，直接替换外层 `styleId`，不把卡片自带的四级标题误判为非法内容。
3. 否则将选区扩展到其覆盖的完整 Markdown 逻辑块，包括完整段落或完整列表项。
4. 校验内容类型；失败时提示原因且 Markdown 保持逐字符不变。
5. 校验通过后写入一对 `:::ogzh-card` 指令。
6. 双槽位卡在正文前插入默认四级标题，并自动选中标题占位。
7. 面板关闭、编辑器重新获得焦点，预览立即更新。

### 6.3 无选区时插入

- 单槽位卡插入正文占位“在这里输入卡片内容”，随后选中该占位。
- 双槽位卡插入标题和正文占位，随后先选中标题占位。
- 插入位置使用当前缓存光标，不因点击面板而跳到文档末尾。

### 6.4 替换与移除

- 重新选择另一张卡时只替换外层 ID，不增加嵌套。
- “移除卡片”只删除首尾指令。
- 双槽位卡的四级标题在移除后继续保留。
- 操作完成后保持被处理内容处于可见区域，并提供简短成功提示。

## 7. 首版 10 张卡片

卡片样式只使用微信可稳定保留的静态 HTML 和内联 CSS。禁止 Grid、交互脚本、伪元素和外部样式依赖；需要装饰字符时输出真实、`aria-hidden` 的元素。

| ID | 名称 | 槽位 | 结构 |
| --- | --- | --- | --- |
| `accent-bar` | 左线强调卡 | 正文 | 柔和底色、左侧强调线、轻圆角 |
| `minimal-outline` | 极简框线卡 | 正文 | 透明底、单层细边框、轻圆角 |
| `soft-fill` | 柔和底色卡 | 正文 | 无边框、柔和底色、大圆角 |
| `quote-frame` | 引号金句卡 | 正文 | 细框线、真实引号装饰元素 |
| `top-rule` | 顶线观点卡 | 正文 | 顶部强调线、柔和底色 |
| `double-frame` | 双层框线卡 | 正文 | `double` 边框，不增加嵌套布局 |
| `solid-contrast` | 实色反差卡 | 正文 | 强调色实底、动态选择可读文字色 |
| `capsule-title` | 胶囊标题卡 | 标题＋正文 | 居中胶囊标题、框线正文 |
| `label-title` | 标签标题卡 | 标题＋正文 | 顶部实色标题条、柔和正文底 |
| `numbered-conclusion` | 编号结论卡 | 标题＋正文 | 可编辑数字前缀、结论标题和正文；导出结构用 presentation table 或等价安全结构，不使用 Flex/Grid |

`numbered-conclusion` 的默认标题为“01 阶段结论”。渲染器只在标题以一至两位数字开头时把数字提取为徽标；否则按普通标题展示，不能丢弃用户标题。

## 8. 主题色与可读性

注册表不保存固定业务配色，而是解析以下语义 token：

- `accent`：强调线、标题条和徽标。
- `body`：正文颜色。
- `muted`：次要说明。
- `line`：边框。
- `soft`：浅底卡片背景。
- `surface`：无底色卡片的表面背景。

优先读取 `theme.gzh`；缺失时从当前主题的标题、正文、引用和表格样式中推导。推导失败才使用中性默认值。

`solid-contrast`、标题条和徽标必须根据实际背景计算文字颜色，正文文字对比度目标为 4.5:1。测试必须覆盖全部当前文章主题、普通暗色预览和原生深色主题，不能只验证某一套模板。

## 9. 组件与数据流

```text
编辑器选区
  → 内容与边界校验
  → 写入、替换或移除 Markdown 指令
  → markdown-it 解析卡片容器
  → 卡片注册表按 styleId 生成结构
  → 解析当前主题语义色并写入内联 CSS
  → 同一 renderedHTML 用于预览与公众号复制
```

### 9.1 卡片注册表

新增 `assets/scripts/core/card-styles.js`，集中维护：

- 10 个稳定 ID、中文名称和槽位类型。
- 缩略图所需的预览元数据。
- Markdown 指令序列化、识别、替换和无损移除的纯函数。
- 选区内容合法性检查。
- 主题语义色解析。
- DOM 内联化和少量必要的安全结构转换。

注册表是唯一事实源；面板、解析器和渲染器不得分别维护第二份卡片清单。

### 9.2 Markdown 解析

在 `assets/scripts/core/markdown-engine.js` 注册轻量块规则：

- 识别 `:::ogzh-card <styleId>`。
- 为渲染节点添加白名单后的 `data-ogzh-card`。
- 内部内容继续走现有 Markdown 解析。
- 不引入 `markdown-it-container` 或其他新依赖。

### 9.3 渲染

在 `assets/scripts/core/render-pipeline.js` 的统一内联样式阶段调用 `applyCardStyles(doc, styleConfig)`：

- 先让主题处理普通 Markdown 元素，再追加卡片容器和必要子元素的内联样式。
- 预览和复制继续消费同一份 `renderedHTML`。
- 不在 `clipboard-exporter.js` 另写一套卡片样式。

### 9.4 编辑器集成

在 `assets/scripts/main.js` 复用现有 `editorSelection`、`getEditorSelection()` 和光标恢复逻辑，新增：

- 打开和关闭卡片面板。
- 选区扩展与内容校验。
- 套用、直接插入、替换和移除动作。
- 标题或正文占位选中。
- 成功和失败提示。

当前工作区已经存在一组范围更大的未提交样式覆盖改动。实施时必须做精准拆分，不能整棵工作区回退，也不能把错误范围一起交付。

### 删除或不纳入本功能

- `documents[].styleOverride`、样式 front matter 和自由 CSS 合并。
- 文档中声称上述广义能力已经属于本次需求的描述。

### 更新并复用

- 现有编辑器选区缓存、插入、焦点恢复能力。
- 主题语义色推导中经过验证且确有需要的最小纯函数。
- 预览和复制共用渲染结果的既有管线。

### 补充

- 10 张固定卡片注册表。
- 白名单 Markdown 指令。
- 卡片内容边界和无损替换测试。
- 全主题对比度与微信公众号粘贴验收。

实施前先用 `git diff` 按文件和函数确认归属；保留排版简化、DepthCarousel 等与本功能无关的用户改动，不得通过整文件回退清理工作区。

## 12. 错误处理

| 场景 | 行为 |
| --- | --- |
| 选区含标题、图片、表格、代码块、原始 HTML | 面板中 10 张卡片按钮全部禁用并显示具体原因；动作层再次校验，Markdown 不变 |
| 选区跨越现有卡片边界 | 面板中 10 张卡片按钮全部禁用，提示先缩小选区或移除原卡片；Markdown 不变 |
| 光标位于现有卡片内 | 允许替换或移除当前卡片 |
| 未知卡片 ID | 显示内部内容，不应用卡片外观 |
| 指令未闭合 | 保留原始文本，不猜测修复 |
| 主题 token 缺失 | 使用推导值；仍缺失时使用中性安全默认值 |
| 颜色对比度不足 | 自动选择更深的背景或黑/白文字，达到目标后再渲染 |

## 13. 测试与验收

### 13.1 自动测试

1. 注册表恰好包含 10 个唯一、稳定 ID，7 个单槽位和 3 个双槽位。
2. 单槽位和双槽位指令能解析并保留内部 Markdown。
3. 有选区套用、无选区插入、换卡、移除能够逐字符往返。
4. 部分文本选区会扩展到完整段落或完整列表项，前后正文不被修改。
5. 非法内容、跨卡片边界和嵌套请求不会修改 Markdown。
6. 未知或损坏指令不会吞掉正文。
7. 10 张卡片都输出内联样式，不依赖页面 CSS 才能成立。
8. 全部当前文章主题下正文和实色区域满足对比度规则。
9. 深色预览不会对原生深色主题重复反色。
10. `npm test` 全量通过，`git diff --check` 无错误。

### 13.2 浏览器验收

- 鼠标与键盘均可打开面板、选择卡片、关闭面板。
- 点击面板后编辑器选区不丢失，插入位置不跳到文末。
- 10 张缩略图与实际渲染结构一致。
- 桌面两列、窄屏单列，无横向溢出。
- 套用、替换和移除后焦点位置符合约定。

### 13.3 微信公众号验收

至少选择浅色、彩色和原生深色文章主题各一套：

1. 把包含 10 张卡片的文章复制到微信公众号后台。
2. 检查边框、底色、圆角、标题、引号和编号结构。
3. 检查桌面和手机预览，确认无横向溢出。
4. 检查深色模式或智能反色后的文字可读性。

本地预览和自动测试通过不等于微信公众号验收完成。

## 14. 发布与回滚

### 发布顺序

1. 完成纯函数和注册表测试。
2. 接入 Markdown 解析和渲染，跑全量自动测试。
3. 接入编辑器工具栏和交互。
4. 完成桌面、窄屏和微信公众号粘贴验收。
5. 以单一、可回退提交发布，不增加运行时开关。

### 回滚

- 发布前失败：撤销本功能提交，不触碰其他工作区改动。
- 已有用户保存卡片标记后：可隐藏工具栏和停用新建，但必须保留指令解析与“显示内部内容”的降级能力，避免历史文档暴露标记或丢失正文。

## 15. 完成定义

只有同时满足以下条件，功能才算完成：

- 10 张卡片全部可通过编辑器选区套用或直接插入。
- 可替换、可无损移除、不能嵌套。
- Markdown 导入导出后卡片仍存在。
- 全主题对比度回归通过。
- 预览与复制共用同一内联样式结果。
- 微信公众号后台实测通过。
- 当前工作区中与本需求无关的未提交改动保持不变。
