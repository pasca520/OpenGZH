# 目录优先的 Markdown 导入与主题表格图片设计

## 背景

OpenGZH 当前通过单文件选择器读取 Markdown。浏览器只向页面提供所选文件本身，不提供其父目录句柄或可用的本机绝对路径，因此页面无法自动读取与 Markdown 同目录的图片。

现有导入流程会在扫描到本地图片引用后再次要求用户选择目录，但解析器只按文件名查询所选目录根层。它无法正确处理嵌套相对路径，也无法区分不同目录中的同名图片。未匹配图片会保留原路径；复制流程虽然记录图片转换失败，最后仍可能提示“复制成功”，存在静默丢图风险。

Markdown 表格目前会套用正文主题并作为 HTML `<table>` 复制到公众号。公众号编辑器可能改变表格宽度、边框和单元格样式，无法保证预览与粘贴结果一致。

## 目标

- 将“导入 MD”改为目录优先：一次授权即可读取 Markdown 及其同目录、子目录中的图片。
- 以 Markdown 所在目录为基准精确解析本地图片路径；只有自动解析失败时才让用户补选图片目录。
- 保留现有“压缩 + IndexedDB + `img://` + 复制时 Base64”链路。
- 复制前验证所有图片可用，存在缺图时阻止复制并明确列出路径。
- 复制到公众号时，将 Markdown 表格按当前正文主题生成 2× PNG，避免公众号重排表格样式。
- Markdown 源文和站内预览仍保留可编辑、可选择文本的 HTML 表格。

## 非目标

- 不允许网页直接读取用户输入的 `/Users/...`、`C:\\...` 或 `file://...` 绝对路径；浏览器必须先获得目录授权。
- 不引入桌面壳、本地服务、图床或后端上传接口。
- 不修改正文主题定义，也不让封面模板参与正文表格样式。
- 不把生成的表格图片写回 Markdown，不改变用户原始表格内容。
- 不新增表格图片配置项；复制到公众号时默认自动转换。
- 不改变现有 GIF 占位提示策略。

## 方案选择

采用“目录优先导入 + 复制阶段表格栅格化”。

不继续采用“先选单个 MD、再选图片目录”，因为浏览器无法从单个 `File` 反查其父目录，该方案不能实现同目录自动导入。也不采用桌面端或本地服务读取绝对路径，因为会破坏当前纯前端、静态部署的产品边界。

表格只在复制副本中转成图片。导入时提前转图会丢失编辑能力，并且切换正文主题后必须重新生成；保留 HTML 表格复制则无法稳定抵抗公众号编辑器的样式重写。

## 用户流程

### 导入

1. 用户点击“导入 MD”，选择包含文章的目录。
2. 目录根层只有一个 `.md` 或 `.markdown` 文件时直接导入；存在多个时显示文件名列表，让用户选择一篇。
3. 系统扫描文章中的本地图片引用，并以所选 Markdown 所在目录为基准解析。
4. 同目录和相对路径全部解析成功时直接完成导入，不再要求额外操作。
5. 存在未找到图片时，显示缺失路径清单，并提供“选择图片目录”操作。
6. 用户补选目录后再次匹配；仍然缺失或存在同名冲突时保留缺失状态，不静默猜测。
7. 已找到图片经过现有压缩器写入 IndexedDB，Markdown 引用替换为 `img://<id>`，随后创建新文档。

### 复制到公众号

1. 从当前渲染结果创建独立副本，不修改编辑区和预览区 DOM。
2. 读取所有 `data-image-id` 对应的 IndexedDB Blob，并处理当前允许复制的远程图片。
3. 任一图片无法读取或转换时停止复制，提示缺失数量与可定位的原始路径或图片名称。
4. 在保留表格文本的情况下先生成 `text/plain` 剪贴板内容。
5. 等待 `document.fonts.ready`，将每个表格按当前正文主题和正文背景生成 2× PNG。
6. 用生成图片替换复制副本中的表格，再沿用现有图片 Base64 转换和富文本剪贴板写入流程。
7. 全部图片和表格处理成功后才显示“复制成功”。

## 路径解析规则

本地图片路径统一标准化后匹配：

- `image.png`、`./image.png`：Markdown 同目录。
- `images/image.png`：Markdown 同目录下的 `images` 子目录。
- `../images/image.png`：仅当规范化结果仍位于用户已授权的目录内时允许读取。
- Windows 反斜杠转换为路径分隔符；安全解码 `%20` 等 URL 编码。
- `http://`、`https://`、`data:`、`img://` 和锚点继续视为非本地路径。
- 路径规范化后越过授权目录边界时不尝试读取，进入缺失清单。
- 解析出的文件必须是可解码图片；非图片文件即使路径同名也不得写入图片存储。

补选图片目录后，优先按完整相对路径匹配；无法匹配时只允许唯一文件名命中。同一目录树存在两个同名候选时标记冲突，不选择任意一个。

第一版覆盖 Markdown 行内图片、带标题的图片、引用式图片定义，以及 HTML `<img src="...">`。路径扫描与重写必须保持 alt、title 和引用标签不变。

## 目录读取与兼容

支持 `showDirectoryPicker` 时使用只读目录句柄，并按引用路径逐级读取，避免无条件遍历整个目录。API 不可用时，回退到隐藏的目录文件输入，通过 `webkitdirectory` 与 `webkitRelativePath` 构造路径到 `File` 的映射。

目录授权只用于本次导入；图片入库后依靠现有 IndexedDB 持久化，不保存长期目录权限，也不在刷新后重新读取用户磁盘。

## 表格图片生成

新增一个独立的表格图片渲染单元，由公众号剪贴板导出器调用。它接收已经内联正文主题样式的表格节点和正文背景色，返回 PNG Blob 或明确错误，不负责扫描 Markdown、写 IndexedDB 或写剪贴板。

实现保持零运行时依赖：把表格克隆到离屏容器完成真实布局，将结果序列化到 SVG `foreignObject`，再通过 Canvas 输出 PNG。生成前需满足：

- 表格内部图片已经转为 Data URL，避免 Canvas 污染或异步空白。
- 所有字体已经就绪。
- 离屏容器复用现有 `--preview-width-tablet` 正文逻辑宽度（当前为 750px），不受当前桌面/手机预览模式影响；变量不可读时才回退到 750px。
- 表格、表头、单元格、字体、边框、背景和内边距来自当前正文主题的已内联样式。
- Canvas 宽高为逻辑尺寸的 2 倍，粘贴后的 CSS 显示宽度保持 100%、高度自动。

如果浏览器不支持所需栅格化能力、Canvas 返回空 Blob、表格超过运行时允许尺寸或表格内资源无法内联，则中止本次复制并提示用户拆分或修复表格。第一版不自动切分超长表格，避免引入表头复制、跨行单元格切分等额外语义。

表格转图的明确取舍是：公众号中的表格文字不可选择、链接不可点击，但换取跨主题和公众号编辑器的稳定视觉结果。Markdown、站内预览和 `text/plain` 剪贴板仍保留表格文本。

## 代码边界

- `index.html`
  - 将导入入口接到目录选择流程。
  - 提供多 Markdown 文件选择和缺图清单所需的最小界面。
  - `showDirectoryPicker` 不可用时使用 `webkitdirectory` 目录文件输入，不回退到无法访问同目录资源的单文件主流程。
- `assets/scripts/main.js`
  - 编排目录授权、Markdown 选择、导入结果提示和文档创建。
  - 不实现路径遍历或表格绘制细节。
- `assets/scripts/core/markdown-image-resolver.js`
  - 扩展为基于 Markdown 目录句柄或路径映射的解析器。
  - 负责路径标准化、精确匹配、补充目录匹配、冲突报告和 Markdown 重写。
  - 保留 `resolvedMarkdown`、`matched`、`unmatched` 的现有返回语义，新增 `conflicts` 和来源路径信息。
- `assets/scripts/export/table-image-renderer.js`
  - 新增独立表格到 PNG 转换函数。
  - 负责字体等待、离屏测量、SVG/Canvas 转换和资源释放。
- `assets/scripts/export/clipboard-exporter.js`
  - 调整图片预检与表格转换顺序。
  - 任一资源失败时返回失败，不再继续写入剪贴板或显示最终成功提示。
- `assets/scripts/core/__tests__/markdown-image-resolver.test.js`
  - 扩展目录和路径边界用例。
- `assets/scripts/export/__tests__/table-image-renderer.test.js`
  - 新增表格尺寸、样式、字体等待、2× 输出和失败回退测试。
- `assets/scripts/export/__tests__/clipboard-exporter.test.js`
  - 新增复制前完整性和成功提示约束测试。

不修改 `ImageStore` 数据库名称、版本、对象仓库和 `img://` 协议，不需要数据迁移。

## 错误处理

- 用户取消首次目录选择：不创建文档，不修改当前编辑内容。
- 目录根层没有 Markdown：提示重新选择文章目录。
- 多个 Markdown：等待用户选择，不默认导入第一篇。
- 补选图片目录取消：允许文章进入编辑器，但保留缺图提示；复制阶段必须阻止带缺图的内容。
- 同名图片冲突：显示冲突路径，不按遍历顺序猜测。
- IndexedDB 写入失败：该图片视为未导入，文档不引用不存在的 `img://` ID。
- 复制预检失败：不调用 `navigator.clipboard.write`，不显示“复制成功”。
- 表格转图失败：不回退到不稳定 HTML 表格，阻止复制并说明失败表格序号。
- 表格替换图片提供由列名和行数生成的 alt 摘要；完整表格文字保留在 `text/plain` 剪贴板内容中。

## 测试

### 自动测试

- 同目录裸文件名和 `./` 路径自动命中。
- 多级子目录、授权范围内的 `../`、中文名、空格、URL 编码和 Windows 分隔符正确解析。
- 越过授权目录、缺失文件和同名冲突不会误匹配。
- 补选目录优先完整相对路径，只接受唯一文件名候选。
- Markdown 行内、带 title、引用式和 HTML 图片在重写后保持原有文本属性。
- 部分图片写库失败时不生成悬空 `img://` 引用。
- 表格渲染等待字体，保留主题背景、表头、边框和字号，输出尺寸为逻辑尺寸 2 倍。
- 多个表格各自生成图片，原始 Markdown 与预览 HTML 不变。
- 图片、表格任一处理失败时剪贴板不写入，且不会发送成功 Toast。
- `npm test` 与 `git diff --check` 通过。

### 浏览器验收

- 在 HTTPS 线上环境和 localhost 各导入一次包含同目录图片、子目录图片和缺失图片的样例目录。
- 导入后刷新页面，已入库图片仍可显示。
- 切换有浅色、深色和特殊表格样式的正文主题，生成图片与当前预览风格一致。
- 将包含普通表格、宽表格、中文长文本和单元格内图片的文章复制到公众号后台，确认图片完整、文字清晰且没有 HTML 表格样式漂移。
- 模拟删除 IndexedDB 图片记录后复制，必须被阻止并显示可定位的缺失信息。

## 验收标准

- 用户导入图片与 Markdown 同目录的文章时，只需选择一次文章目录。
- 相对路径解析基于 Markdown 位置，不再仅按文件名查询目录根层。
- 自动解析失败后才出现补选图片目录操作，补选后无歧义图片可以完成入库。
- 已匹配图片全部转换为 `img://` 并在刷新后继续可用。
- 任一图片缺失时不能出现最终“复制成功”。
- 每个 Markdown 表格在公众号富文本中表现为当前正文主题的 2× PNG；Markdown 和预览仍是 HTML 表格。
- 表格转换或剪贴板写入失败时保留当前编辑内容，并给出明确错误。
- 不新增运行时依赖，不改变现有 IndexedDB 和文档存储格式。

## 发布与回滚

先使用包含同目录、嵌套、缺失和重名图片的本地样例完成浏览器验证，再在真实公众号后台检查浅色、深色主题的表格图片粘贴结果。公众号实测通过前不宣称发布链路完全可用。

若目录导入出现兼容问题，可恢复原单文件导入入口；已写入的 `img://` 内容继续兼容。若表格栅格化出现浏览器兼容问题，可回滚表格渲染器及剪贴板调用点，恢复当前 HTML 表格复制。两部分均不涉及存储迁移，回滚不需要清理用户数据。
