# 人人登录检测与分发弹窗调优设计

**状态：** 交互方案已确认，等待书面规格复核

**日期：** 2026-08-26

## 目标

本次只解决两个已确认问题：

1. 已登录“人人都是产品经理”时，OpenGZH 仍提示“人人登录页认证结构已变化”。
2. 多平台分发弹窗缺少清晰的信息层级与完整视觉样式，平台状态、登录操作和主操作难以快速判断。

保持现有四平台同步协议、串行任务模型、文章快照、图片上传、草稿保存、打开草稿和权限边界不变。不新增依赖，不自动发布文章，不扩大扩展权限。

## 现状与根因

2026-08-26 在已登录的人人写作页 `/writing` 中核对到：

- 当前页面使用顶层可执行脚本中的 `var PURE = {...}` 暴露 `is_user_logged_in`、`user_id` 与 `jltoken`。
- 页面仍使用独立的 `var userSettings = {...}` 暴露 `uid`。
- `/api2/user/profile?uid=...` 仍返回 HTTP 200、业务码 200，且资料 UID 与页面 UID 一致。

现有 `WoshipmAdapter` 只接受旧结构 `window.settings.jltoken + var userSettings.uid`。因此它能读到 UID，却读不到新位置中的 token，随后按安全策略抛出 `PLATFORM_CHANGED`。用户看到的错误来自过时的页面结构解析，不是登录会话失效，也不是资料接口异常。

弹窗目前只有少量布局 CSS，按钮、复选框、标题与状态缺少完整组件样式。关闭按钮占据首行，标题与说明冗长；每个平台行同时承载选择、状态和多个默认按钮；底部主操作没有独立操作区，导致视觉层级接近浏览器原生表单。

## 方案选择

采用“兼容解析器 + 原 Shadow DOM 内渐进式重排”。

不采用两步向导：平台只有四个，任务也只有一次选择和一次保存，引入步骤状态会增加操作成本。

不采用侧边抽屉：抽屉更容易遮挡编辑器、扩大响应式改动范围，也不能改善平台状态本身的表达。

当前方案复用既有适配器、状态机、DOM 元素和 Shadow DOM 隔离，只增加当前认证结构的严格解析，以及弹窗必要的语义容器、状态属性和样式。

## 人人登录检测设计

### 接受的认证结构

`extractPageAuth()` 同时识别以下两种页面版本，但单个页面只能产生一组无冲突的认证结果：

- 旧结构：顶层 `window.settings = {...}` 中的 `jltoken`。
- 当前结构：顶层 `var PURE = {...}` 中的 `jltoken`、`is_user_logged_in` 和 `user_id`。

UID 继续从顶层 `var userSettings = {...}` 的 `uid` 读取。当前结构还必须满足 `PURE.user_id === userSettings.uid`。

解析器只读取顶层、可执行 JavaScript 中的对象字面量；不执行页面脚本，不接受函数体、条件分支、字符串、注释、正则、模板或惰性 HTML 容器中的伪造字段。

### 判定规则

- 当前结构明确标记未登录时，返回 `{ authenticated: false }`，不请求用户资料。
- 认证字段全部缺失时，沿用未登录结果。
- 只出现 UID、只出现 token、UID 冲突、重复认证对象、非法 token 或对象无法完整解析时，继续抛出 `PLATFORM_CHANGED`。
- 得到完整认证信息后，继续请求固定的用户资料接口，并校验业务码、资料结构、UID 与昵称。
- 只有资料校验通过后才把 token 留在适配器实例内存中，供紧接着的图片上传与草稿保存使用。
- token 不进入返回值、错误、日志、存储、测试快照或页面 UI；任一后续鉴权/网络异常继续清空内存 token。

该修复不放宽固定域名、HTTPS、默认端口、重定向、请求头规则或敏感数据持久化边界。

## 弹窗信息架构

### 顶部

- 主标题改为“同步到内容平台”，直接表达本次任务。
- 说明改为“选择平台，确认登录状态后保存为草稿。”
- “关闭”文字按钮改为右上角图标按钮，保留 `aria-label="关闭"`、键盘焦点和焦点恢复。
- 保留 `role="dialog"`、`aria-modal="true"` 与标题关联。

### 平台状态列表

每个平台保持一行状态卡，顺序仍为微信公众号、知乎、掘金、人人都是产品经理：

- 左侧：原生复选框、平台识别块与平台名。
- 中部：状态文本，使用状态色和小圆点区分检测中、已登录、需要登录、处理中、成功、失败和未选择。
- 右侧：只展示当前可执行的操作，不显示无效的灰色按钮。

操作可见性固定为：

- `checking-auth`、处理中、`unselected`：不显示行操作。
- `authenticated`：不显示登录或重检。
- `auth-required`：显示“去登录”和“重新检测”。
- `failed`：显示“重新检测”，不把平台结构错误伪装成未登录。
- `success`：只显示“打开草稿”。
- `unknown`：不允许盲目重试，继续提示人工检查草稿箱。

状态文本保留 `aria-live="polite"`。错误文案允许换行，不用省略号隐藏关键原因；长错误被限制在平台行内，不撑破弹窗。

### 底部操作区

- 独立 footer 展示固定说明“只保存草稿，不会自动发布”。
- “保存草稿并打开”是弹窗内唯一高强调主按钮。
- 未选择平台或任务执行中时使用明确的禁用样式；连接、快照和批次错误继续进入现有 `role="alert"` 区域。
- 批次执行期间锁定平台选择和相关操作，保持现有任务一致性。

## 视觉系统

只在内容脚本 Shadow DOM 内定义局部 token，不影响 OpenGZH 页面和文章输出：

- 背景：白色面板、轻灰平台卡片、深色正文。
- 主色：沿用可信赖的蓝色，用于主按钮、焦点环和选中状态。
- 成功：绿色；需登录/警告：琥珀色；失败：红色；未选择：中性灰。
- 圆角：面板 18px，平台卡片 12px，按钮 10px。
- 阴影：单层柔和面板阴影；遮罩增加轻微模糊，避免厚重玻璃拟态。
- 动效：仅使用 160–200ms 的颜色、阴影和位移过渡；`prefers-reduced-motion: reduce` 时移除过渡。

按钮、链接、复选框必须有 hover、active、disabled 与 `:focus-visible` 状态。正文和状态文本达到 WCAG AA 对比度。

## 响应式与可访问性

- 桌面弹窗宽度控制在约 560px，最大高度不超过视口并允许内容区滚动。
- 560px 以下平台卡片改为两行：平台信息在上，操作区在下。
- 390px 视口下保持 16px 安全边距、至少 44px 的可点击高度，底部主按钮可占满可用宽度。
- Escape、点击遮罩、关闭按钮都关闭弹窗并把焦点还给网页入口。
- Tab/Shift+Tab 继续在 Shadow DOM 弹窗内循环，不改变既有焦点陷阱。
- 平台文字图标继续标记 `aria-hidden="true"`；图标不代替平台名或按钮标签。

## 最小改动范围

- `extension/src/adapters/woshipm.js`：增加当前 `PURE` 认证结构的严格解析与一致性校验。
- `extension/tests/adapters/woshipm.test.js`：增加当前登录结构、明确未登录、冲突和伪造结构回归测试。
- `extension/src/content/open-gzh.js`：调整弹窗语义容器、操作可见性、状态属性和 Shadow DOM 样式。
- `extension/tests/content-script.test.js`：锁定新信息层级、状态操作、样式、焦点与响应式契约。

不修改 service worker 协议、任务关联字段、平台顺序、其他三个适配器、Manifest 权限和网页文章渲染。

## 测试与验收

### 自动化

1. 先增加当前 `PURE` 登录页 fixture，确认旧实现因 `PLATFORM_CHANGED` 失败。
2. 实现最小兼容解析后，确认旧结构和当前结构均通过资料校验。
3. 覆盖未登录标志、UID 冲突、重复对象、非法 token、惰性脚本和脚本伪造字段，确认失败关闭。
4. 增加 UI DOM/CSS 契约测试，确认关闭按钮、标题、footer、状态属性和上下文操作可见性。
5. 运行人人适配器测试、内容脚本测试、扩展专项测试、全量测试、扩展构建、`node --check` 与 `git diff --check`。

### 真实浏览器

1. 重新构建并在 `chrome://extensions` 手动重载当前扩展。
2. 在用户已登录的人人账号中只执行登录检测，确认显示“已登录”；不创建草稿。
3. 在桌面宽度和 390px 宽度检查平台状态、按钮可见性、滚动、键盘焦点与关闭后的焦点恢复。
4. 检查扩展错误页和控制台没有 Manifest、service worker 或内容脚本错误。

真实草稿创建属于第三方写操作，不包含在本次登录检测与 UI 验收中；如需执行，必须再次取得用户确认。

## 验收标准

1. 人人当前 `PURE` 登录结构通过资料接口交叉校验后显示“已登录”。
2. 旧 `window.settings` 结构继续通过，未登录与异常结构仍然失败关闭。
3. 弹窗不再出现浏览器默认按钮观感，关闭、标题、平台状态和主操作形成明确层级。
4. 不可执行的登录/重检操作不显示；失败不再一律显示“登录”。
5. 1440px 桌面与 390px 移动视口无横向溢出，键盘焦点和状态播报正常。
6. 四平台协议、文章快照和批次任务现有回归测试保持通过。
7. 不新增权限、依赖、凭据存储或自动发布行为。
