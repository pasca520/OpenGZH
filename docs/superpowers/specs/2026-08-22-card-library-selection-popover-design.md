# OpenGZH 卡片库扩展与选区浮层设计

日期：2026-08-22

状态：设计已确认，待实施计划

范围：文本模式卡片库、卡片装饰 GIF 复制、Markdown 编辑器选区浮层；不扩展全文主题或通用素材平台

## 1. 背景与目标

现有卡片库有 10 张卡片，入口位于编辑器顶部工具栏。用户需要完成三项调整：

1. 从可选卡片中去掉「左线强调卡」「双层框线卡」「标签标题卡」。
2. 新增 11 张更有设计感的卡片，覆盖底色、框线、底纹、结构化内容和 5 种可复制 GIF 装饰；最终可选卡片为 18 张。
3. 选中文字后直接在选区右侧显示卡片浮层，不再经过顶部「卡片」按钮。

实现必须继续遵守现有 Markdown 指令、主题色、预览与公众号复制共用渲染链路。旧文档不得因卡片下架而丢失样式或内容。

## 2. 非目标

- 不增加用户自建卡片、自由 CSS、远程素材市场、搜索或收藏。
- 不把加粗、链接、引用等通用格式塞进选区浮层。
- 不在右侧预览区反向编辑 Markdown。
- 不新增后端、构建步骤或运行时依赖。
- 不提供卡片参数面板；卡片保持固定结构并跟随主题语义色。
- 不继续支持「无选区插入空卡片」入口；卡片操作从有效文字选区开始。
- 不把整张卡片栅格化；正文和链接在复制后必须仍是文字。

## 3. 已确认的产品决策

| 决策 | 结论 |
| --- | --- |
| 可选卡片数量 | 18 张：13 张静态、5 张含 GIF 装饰 |
| 下架卡片 | 左线强调卡、双层框线卡、标签标题卡 |
| 旧文档兼容 | 3 个旧 ID 继续可渲染、替换和移除，但不再出现在浮层中 |
| 新增静态卡 | 柔光晕染、细格纸纹、斜纹注释、折角便签、括号观点、双色索引 |
| 新增动效卡 | 高光摘录、步骤接力、关系编织、书签提醒、历史文档 |
| 动效范围 | 只动装饰，正文不位移；动作完成后保留静止阅读时间 |
| GIF 复制 | 预览用 CSS 动效，复制时只把装饰区替换为透明背景 GIF |
| 历史文档结构 | 单行「序号｜文档名｜日期或作者」，无英文、无说明小字 |
| 桌面入口 | 非空选区形成后，卡片浮层直接出现在选区焦点右侧 |
| 浮层标题 | 「应用卡片样式」与浅灰状态标签「已选 N 字」同一行，无分隔符 |
| 浮层筛选 | 全部 18、静态 13、动效 5 |
| 窄屏行为 | 小于等于 768px 时使用底部半屏面板 |
| 卡片操作 | 新选区套用；现有卡片内选区可替换或移除 |

## 4. 方案比较

### 4.1 卡片与动效

#### 方案 A：统一编辑部卡片体系，局部语义动效（采用）

11 张新卡共享主题 token 和排版节奏，按底色、框线、底纹、结构和动效分工。动效分别表达强调、步骤、关系、提醒和档案，不使用无意义的旋转圆点或扫描线。

优点：设计丰富但仍像同一个产品；公众号长文中可混用；动效有内容语义。缺点：需要扩展装饰渲染和 GIF 生成。

#### 方案 B：11 张独立海报式卡片

优点：单张记忆点强。缺点：跨主题和长文组合容易杂乱，不利于形成稳定卡片库。

#### 方案 C：静态卡片与通用动效贴纸自由组合

优点：组合数量多。缺点：编辑步骤增加，装饰容易与内容语义不匹配，超出本轮固定卡片范围。

### 4.2 选区入口

#### 方案 A：选区右侧直接浮层（采用）

选区形成后立即分析内容并显示卡片选择器；桌面优先右侧，空间不足翻到左侧或钳制到编辑区可视范围。

优点：符合「选中即编辑」，省去顶部入口和二次点击。缺点：需要准确测量 textarea 选区位置。

#### 方案 B：固定在编辑器右上角

优点：定位简单。缺点：与选区缺少空间关联，长文滚动时需要视线跳转。

#### 方案 C：保留顶部按钮，只缓存选区

优点：改动最小。缺点：没有解决用户要求的直接编辑路径。

## 6. Markdown 与内容合同

### 6.1 通用卡片

继续使用现有指令：

```md
:::ogzh-card soft-halo
这里是卡片正文。
:::
```

标题＋正文卡继续使用四级 Markdown 标题：

```md
:::ogzh-card relationship-weave
#### 系统关系

真正的价值来自目标、流程和角色的协同。
:::
```

### 6.2 历史文档卡

默认片段：

```md
:::ogzh-card history-document
#### 历史文档

- 第一版方案 ｜ 2026.08.12
- 第二版方案 ｜ 2026.08.18
- 当前版本 ｜ 2026.08.22
:::
```

规则：

- 每个直接列表项渲染为一行：两位序号、文档名称、右侧元信息。
- 分隔符优先使用全角 `｜`，同时接受半角 `|`；只拆分最后一个分隔符。
- 右侧元信息可写日期或作者，不增加专有字段。
- 文档名称允许普通文本或链接；链接在预览和复制后继续可点击。
- 不渲染说明小字、英文标签、类型或版本副标题。
- 文档名称过长时单行省略，右侧元信息始终保留。
- 没有分隔符时仍显示该行，右侧留空，不丢弃内容。

## 7. 视觉与动效合同

### 7.1 主题和复制安全

- 所有卡片继续解析 `accent`、`body`、`muted`、`line`、`soft`、`surface` 六个语义 token。
- 正文和标题对比度目标保持 4.5:1，并覆盖普通预览与原生深色主题。
- 导出结构不依赖伪元素、外部 URL 或交互脚本。
- 需要保留的装饰输出为真实、`aria-hidden="true"` 的 DOM 元素。
- 细格与斜纹使用内嵌、同源生成的静态图案数据，不引用网络图片；图案只是装饰，失败时回退到纯底色和框线。
- 正文、标题、列表和链接始终保留为 HTML 文字，不把整张卡片转成图片。

### 7.2 五种动效

| 卡片 | 动效语义 | 周期要求 |
| --- | --- | --- |
| 高光摘录 | 强调标题结论 | 高光出现后停留，正文不动 |
| 步骤接力 | 表达 1→2→3 顺序 | 节点依次点亮，轮次结束后停顿 |
| 关系编织 | 表达要素从分散到连接 | 连线依次建立，节点响应一次后停住 |
| 书签提醒 | 标识注意事项或边界 | 书签轻落一次后停住 |
| 历史文档 | 中性表示多份文档 | 后页轻移、前页响应，随后静止 |

共同约束：

- 正文和标题不位移、不闪烁。
- 动效装饰面积控制在卡片视觉面积约 10% 内；关系编织的独立右侧装饰区除外，但不得覆盖正文。
- 单轮周期为 3.6–5 秒，至少约一半时间保持静止或最终状态。
- 页面预览使用 CSS 动效；`prefers-reduced-motion: reduce` 下直接显示最终静态状态。
- 装饰均为非语义、`aria-hidden` 内容；理解正文不依赖动画。

## 8. GIF 复制链路

复用现有结尾动效的 `gif-encoder.js`，新增卡片装饰生成器，不引入依赖。

```text
renderedHTML 中的卡片装饰
  → 普通图片和公式处理
  → 识别 5 种 data-ogzh-card-animation
  → 按当前主题色逐帧绘制透明 GIF
  → 仅把装饰节点替换为 img[data:image/gif]
  → 写入公众号 ClipboardItem
```

实现约束：

- 新增 `card-decoration-gif.js`，导出动画元数据和 `buildCardDecorationGif()`。
- 同一次复制按「动画类型＋主题色」缓存生成结果，避免重复编码。
- GIF 尺寸按装饰真实占位生成，不生成整卡大图。
- GIF 生成发生在普通图片物化之后，与现有结尾 GIF 一样避免被 GIF 占位逻辑替换。
- 生成失败时记录警告并保留静态装饰，不阻断整篇文章复制。
- 测试检查 GIF 头、尺寸、动画帧差异和缓存键，不用像素截图代替结构测试。

## 9. 选区浮层交互

### 9.1 触发和关闭

- 删除顶部工具栏「卡片」按钮及原锚点面板。
- `selectionStart !== selectionEnd` 时分析选区；鼠标选择和键盘选择都支持。
- 有效选区打开完整卡片浮层；非法选区打开紧凑原因提示，不能静默失败。
- 光标折叠、输入导致选区消失、点击浮层外、按 `Esc` 时关闭。
- 点击浮层使用 `mousedown.prevent` 保留 textarea 选区。
- 应用、替换或移除后关闭浮层，按既有正确顺序恢复选区和滚动锚点：保存 `scrollTop` → `setSelectionRange` → `focus({ preventScroll: true })` → 恢复 `scrollTop`。

### 9.2 桌面定位

- 使用 textarea 镜像测量焦点端字符坐标，不依赖最后一次鼠标坐标，因此键盘选区同样准确。
- 根据 `selectionDirection` 选择焦点端；从 textarea 矩形中扣除内部滚动偏移。
- 浮层使用 `position: fixed`，默认位于焦点端右侧并保留 10–12px 间距。
- 右侧空间不足时翻到左侧；两侧都不足时钳制到编辑面板和视口安全边距内。
- 顶部和底部位置钳制到当前可视区域，列表内部滚动，不让浮层超出视口。
- textarea、页面或可视视口滚动，窗口或编辑面板尺寸变化时重新定位；使用 `requestAnimationFrame` 合并重复测量。

### 9.3 浮层内容

- 宽度约 320–360px，标题行显示「应用卡片样式」和浅灰标签「已选 N 字」，右侧为关闭按钮。
- 筛选项为「全部 18」「静态 13」「动效 5」。
- 卡片使用两列紧凑、真实结构缩略图；内容区域可滚动。
- `↑/↓` 浏览，`Enter` 应用，`Esc` 关闭；所有按钮保留可见焦点。
- 选区位于现有卡片时，底部显示可用的「移除卡片样式」。
- 旧卡片不出现在选项中，但旧卡片内选区仍显示替换和移除能力。

### 9.4 窄屏

- 视口小于等于 768px 时，改为底部半屏面板，不尝试挤到选区右侧。
- 面板保持在 `visualViewport` 内，软键盘出现时更新可用高度和底部位置。
- 卡片列表单列，标题、筛选和关闭入口保持可见；列表自身滚动。
- 选区继续保留，面板关闭后恢复原选区和编辑器滚动位置。

## 10. 组件与数据流

```text
textarea 选区变化
  → 缓存 start / end / direction
  → 校验卡片目标
  → 镜像测量焦点端坐标
  → 桌面右侧浮层 / 移动端底部面板
  → 选择 18 张卡片之一或移除
  → 写入、替换或移除 Markdown 指令
  → markdown-it 解析
  → 主题化卡片结构与 CSS 动效
  → renderedHTML 共用于预览和复制
  → 复制阶段把 5 种装饰转为 GIF
```

注册表仍是卡片事实源：公开可选目录、legacy 渲染定义、筛选计数、缩略图、Markdown 操作和导出动画不得维护互相漂移的重复清单。

## 12. 错误处理与边界

| 场景 | 行为 |
| --- | --- |
| 选区含标题、图片、表格、代码块、原始 HTML | 显示紧凑原因提示，Markdown 不变 |
| 选区跨越卡片边界 | 提示缩小选区或先移除卡片，Markdown 不变 |
| 选区位于同一张现有卡片 | 允许替换或移除 |
| 文档含 3 个下架 ID | 继续渲染；不出现在新选项中 |
| 历史文档行缺少元信息 | 文档名单行显示，右侧留空 |
| 历史文档名过长 | 单行省略，右侧元信息保留 |
| 动效生成失败 | 保留静态装饰，复制继续 |
| 主题 token 缺失 | 继续使用现有推导与中性安全默认值 |
| 选区位置无法测量 | 浮层回退到编辑器右上可视位置，不阻断卡片操作 |
| 移动端软键盘改变视口 | 根据 `visualViewport` 重新钳制底部面板 |

## 13. 测试与验收

### 13.1 自动测试

1. 公开目录恰好 18 个唯一 ID，其中静态 13、动效 5；3 个 legacy ID 不在公开目录但仍可查找和渲染。
2. 11 张新卡能生成预览并跟随主题 token；全部文字对比度满足既有规则。
3. 旧卡片可替换和移除，未知卡片仍不吞正文。
4. 历史文档列表按最后一个 `｜` 或 `|` 拆分，链接保留，序号稳定，缺省元信息不丢内容。
5. 五种动效装饰输出真实 `aria-hidden` 节点；reduced-motion 有最终静态状态。
6. 五种 GIF 有合法头、正确尺寸和随时间变化的帧；失败回退不阻断复制。
7. 复制后的标题、正文、历史文档名称和链接仍是 HTML 文字，不是整卡图片。
8. 非空选区触发浮层；折叠选区关闭；顶部卡片按钮不再存在。
9. 浮层统计为 18 / 13 / 5，筛选结果与注册表一致。
10. 保持选区和滚动锚点的既有回归测试继续通过。
